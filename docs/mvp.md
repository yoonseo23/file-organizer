# File Organizer MVP 기획안

> 작성일: 2026-11-05 · 작성자: 정윤서 · 상태: 초안
> 레포: `github.com/yoonseo23/file-organizer`

---

## 1. 한 줄 요약

macOS에서 바탕화면과 다운로드 폴더에 쌓인 파일을 **명령 한 번으로, 규칙에 따라, 되돌릴 수 있게** 정리해주는 로컬 CLI 도구.

## 2. 문제 정의

- **현재 상황**: 과제 PDF, 스크린샷, 이미지, 설치 파일(`.dmg`), 압축 파일이 바탕화면과 다운로드 폴더에 뒤섞여 쌓인다.
- **불편한 점**: 필요한 파일을 찾을 때 이름도 위치도 기억나지 않고, 하나하나 옮기는 게 귀찮아서 정리를 미루게 된다.
- **기존 대안과 한계**:
  - 수동 정리 → 파일마다 어디로 보낼지 판단하고 드래그하는 게 번거로움
  - Hazel 같은 유료 앱 → 비용, 규칙을 코드로 관리·버전관리하기 어려움
  - macOS 스택 기능 → 바탕화면 겉보기만 정리될 뿐 실제 파일 위치는 그대로

## 3. 대상 사용자

| 사용자                   | 상황                             | 원하는 것                           |
| ------------------------ | -------------------------------- | ----------------------------------- |
| 나 (1차)                 | macOS, 과제·자료 다운로드가 많음 | 정리하고 싶을 때 한 번에 끝내기     |
| 비슷한 학생·직장인 (2차) | 코딩 경험 적음                   | 설정 파일만 고쳐서 내 규칙으로 쓰기 |

## 4. 핵심 가설

> "명령 한 번으로 '어디로 옮길지' 판단까지 대신해주면, 나는 정리를 미루지 않고 **주 1회 이상** 실행하게 된다."

부가 가설: 실행 전에 계획을 보여주고 undo가 있으면, 자동 이동을 불안해하지 않고 확인 후 바로 승인한다.

## 5. MVP 범위

### 5-1. 반드시 포함 (Must)

- [ ] **대상 폴더**: `~/Desktop`, `~/Downloads`
- [ ] **분류 규칙**: 확장자 기준 + 파일명 키워드 기준 (`rules.yaml`로 설정)
- [ ] **확인 후 실행**: 이동 계획을 표로 보여주고 `y/n` 확인을 받은 뒤 이동
- [ ] **안전장치**: 덮어쓰기 금지(이름 충돌 시 `_1`), 삭제 기능 없음
- [ ] **제외 조건**: 다운로드 중인 파일, 숨김 파일, 최근 수정된 파일(기본 10분), **폴더(디렉터리)는 그대로 둠**
- [ ] **기존 폴더 구조에 맞춤**: 규칙마다 이미 쓰고 있는 폴더 경로를 지정, 규칙에 안 맞는 파일은 옮기지 않음
- [ ] **로그 + undo**: 모든 이동을 기록하고, 마지막 실행을 되돌리는 명령

### 5-2. 이번엔 제외 (Won't)

- 계획 표에서 특정 파일만 골라 빼고 실행 → v1.1 (MVP에선 `y/n` 전체 승인만)
- 다운로드된 폴더 이동 → v1.1
- 주기 자동 실행(launchd) → v2 (수동 사용 패턴을 보고 필요하면 추가)
- 실시간 감시(watchdog) → v2 이후
- LLM(Claude API) 기반 분류 → v2
- 날짜별 하위 폴더(`2026-11/`) 자동 생성 → v1.1
- 파일 이름 자동 정리(리네이밍) → v2
- GUI 설정 화면 → v3
- Windows 지원 → 미정

## 6. 핵심 사용 흐름

```
[최초 설정]
1. 레포 clone → `uv tool install -e .` 로 `organize` 명령 등록
2. rules.example.yaml 을 ~/.config/file-organizer/rules.yaml 로 복사 후, 내가 쓰던 폴더 경로에 맞게 규칙 수정

[정리할 때마다]
3. 터미널에서 `organize` 실행
4. 이동 계획 표 확인 (파일 → 목적지, 적용된 규칙)
5. `y` 입력 → 이동 / `n` 입력 → 아무것도 안 함
6. 잘못 옮겨졌으면 `organize undo`, 규칙 수정 후 다시 실행
```

## 7. 인터페이스 (CLI 명령)

| 명령                 | 역할                                 |
| -------------------- | ------------------------------------ |
| `organize`           | 계획 출력 → 확인 후 이동 (기본 동작) |
| `organize --dry-run` | 계획만 출력하고 종료                 |
| `organize --yes`     | 확인 없이 바로 이동 (익숙해진 뒤용)  |
| `organize undo`      | 마지막 실행의 이동을 원래대로        |
| `organize log`       | 최근 실행 기록 보기                  |

출력 예시:

```
정리 대상 12개 (건너뜀 5개: 최근 수정 2, 다운로드 중 1, 폴더 1, 규칙 없음 1)

  파일                         →  목적지                          규칙
  보안시스템_과제2.pdf          →  ~/Documents/학교/               수업자료
  스크린샷 2026-11-04.png       →  ~/Pictures/스크린샷/             스크린샷
  Docker.dmg                   →  ~/Downloads/설치파일/            설치파일
  ...

이동할까요? [y/N]
```

## 8. 기술 스택

| 영역        | 선택                 | 고른 이유                                                                           |
| ----------- | -------------------- | ----------------------------------------------------------------------------------- |
| 언어        | Python 3.12+         | 파일 처리 표준 라이브러리(`pathlib`, `shutil`)가 충분, 학습 자료 많음               |
| 패키지·설치 | `uv`                 | 개발 환경 관리와 전역 `organize` 명령 등록을 한 도구로 처리, 가상환경 활성화 불필요 |
| 설정        | YAML (`PyYAML`)      | 코딩 없이 사람이 읽고 고치기 쉬움                                                   |
| CLI         | `typer`              | 명령·옵션 정의가 간단, 도움말 자동 생성                                             |
| 출력        | `rich`               | 이동 계획을 보기 좋은 표로 출력                                                     |
| 로그 저장   | JSON Lines 파일      | undo에 필요한 원래 경로·이동 경로를 줄 단위로 기록                                  |
| 테스트      | `pytest` + 임시 폴더 | 실제 파일 건드리지 않고 규칙 검증                                                   |

## 9. 데이터 모델

```yaml
# ~/.config/file-organizer/rules.yaml
sources:
  - ~/Desktop
  - ~/Downloads
min_age_minutes: 10
skip_directories: true # 다운로드된 폴더는 그대로 둠
rules: # 위에서부터 먼저 맞는 규칙 적용
  # move_to 경로는 실제로 쓰고 있는 폴더로 교체 (아래는 예시)
  - name: 수업자료
    match: { keywords: ["보안시스템", "과제", "강의"] }
    move_to: ~/Documents/학교/
  - name: 스크린샷
    match: { name_prefix: ["스크린샷", "Screenshot"] }
    move_to: ~/Pictures/스크린샷/
  - name: 문서
    match: { extensions: [pdf, docx, hwp, pptx, xlsx] }
    move_to: ~/Documents/
  - name: 이미지
    match: { extensions: [png, jpg, jpeg, heic, gif, webp] }
    move_to: ~/Pictures/
  - name: 설치파일
    match: { extensions: [dmg, pkg] }
    move_to: ~/Downloads/설치파일/
# 어떤 규칙에도 안 맞는 파일은 옮기지 않고 그대로 둠 (계획 표에 "규칙 없음"으로 표시)
```

```jsonc
// ~/.config/file-organizer/logs/moves.jsonl — 한 줄에 한 이동
{ "run_id": "2026-11-05T15:00", "from": "...", "to": "...", "rule": "문서" }
```

## 10. 보안 · 프라이버시 체크리스트

- [x] 외부 전송 없음 (MVP는 완전 로컬)
- [ ] **삭제 코드 자체를 두지 않음** — 이동만
- [ ] 기본 동작은 확인 후 실행, `--yes`는 명시적으로 줘야 함
- [ ] 정리 대상은 `sources`에 명시된 폴더의 **최상위 파일만** (하위 폴더는 건드리지 않음)
- [ ] 심볼릭 링크는 따라가지 않음
- [ ] 목적지가 `sources` 최상위와 같으면 실행 거부 (무한 이동 방지, 하위 폴더는 허용)
- [ ] **목적지 폴더가 없으면 새로 만들지 않고 경고** — 경로 오타로 엉뚱한 폴더가 생기는 것 방지
- [ ] 개인 경로가 들어간 `rules.yaml`, 로그는 레포 밖 `~/.config/file-organizer/`에 저장 (실수 대비 `.gitignore`에도 등록), 레포엔 `rules.example.yaml`만
- [ ] macOS 권한: 처음 실행 시 터미널에 바탕화면·다운로드 접근 허용 필요 → README에 명시

## 12. 성공 기준

- 2주 실사용 동안 **주 1회 이상** 실행
- 계획 확인 단계에서 `n`을 누르거나 수정이 필요한 비율 10% 미만
- undo 실패 0건, 파일 유실 0건

### 결정됨

- 목적지: 새 폴더를 만들지 않고 **기존 폴더 구조**에 맞춤
- 다운로드된 폴더: **그대로 둠**
- 특정 파일 제외 실행: **MVP에서 제외**
- 설정·로그 위치: **`~/.config/file-organizer/`** (실행 위치와 무관하게 undo가 로그를 찾도록)
- 설치 방식: **`uv tool install -e .`** (가상환경 활성화 없이 어디서나 `organize` 실행)
